## Jak to zostało wygenerowane

Voxtral TTS przez API Mistrala, nie lokalny model:

```bash
cd video && node tts.mjs
```

- model `voxtral-mini-tts-3-0`, głos `voice_3154` (Leon, jedyny polski w katalogu),
- `voxtral-mini-tts-latest` i `voxtral-mini-tts-2603` **nie** obsługują tego głosu
  (błąd `voice is not supported for speech v1`), więc wersja modelu jest przypięta,
- odpowiedź to `{"audio_data": "<base64>"}`, nie surowy plik,
- klucz czytany z `backend/.env` (`LLM_API_KEY`), nie trafia do logów,
- bloki są cache'owane w `/tmp/vidtask/tts`; skasuj katalog, żeby wygenerować od nowa.

Ścieżka dźwiękowa powstaje przez sklejenie bloków z ciszą wypełniającą, nie przez
miksowanie — ten build ffmpeg nie ma `amix normalize`. Na końcu `loudnorm`
do −16 LUFS.

## Wymowa

- `sLaRpNaTiOn` → w syntezie zapisane jako **LARP Nation**. Dosłowne
  `sLaRpNaTiOn` model czyta jako „Eslarb na TYT”. Na ekranie zostaje oryginał.
- `0,90` → „zero przecinek dziewięćdziesiąt”.
- `64%` → „sześćdziesiąt cztery procent”.
- `100%` → „sto procent”.
- `UDIP` → „u-dip”.
- `Mistral Small` → „mistral smol”.
- `Q4_K_M` → w narracji pominięte; jest tylko na karcie modelu w obrazie.

## Weryfikacja

Każdy blok sprawdzony transkrypcją zwrotną (`voxtral-mini-transcribe-3`):
odsłuch segmentów 0 s, 19 s, 61 s i 99 s zwraca dokładnie tekst z tabeli.
Głośność całości: średnia −19,8 dB, szczyt −1,5 dB.

## Podłożenie od zera

`podloz-lektora.sh` kładzie gotowe pliki WAV na znacznikach czasu, jeśli
wolisz własny TTS:

```bash
mkdir lektor
# tu 01.wav, 02.wav, 03.wav, 04a.wav … 04h.wav, 05.wav … 09.wav
./podloz-lektora.sh
```

Jeden ciągły plik zamiast bloków:

```bash
ffmpeg -i asystent-urzednika-bez-dzwieku.mp4 -i narracja.wav \
  -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k \
  asystent-urzednika-lektor.mp4
```
